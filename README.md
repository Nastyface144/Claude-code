# Радар фриланс-заказов в Telegram

Бот следит за биржами фриланса и присылает в Telegram только те заказы, которые
подходят под твои темы:

- **Telegram-боты** (aiogram, pyrogram, telebot, чат-боты, автоматизация);
- **Telegram Mini Apps / TWA** (мини-приложения внутри Telegram);
- **Лендинги** (одностраничные сайты, сайты-визитки, вёрстка).

Всё управление — прямо в чате с ботом: пороги, ключевые слова, источники.

---

## Как это работает

```
Биржи (Kwork,   ──►  парсер  ──►  фильтр по темам  ──►  дедупликация  ──►  Telegram
 RSS других …)         (Order)      (баллы + теги)        (SQLite)         (только новое)
```

1. Раз в `POLL_INTERVAL` секунд бот забирает свежие объявления со всех включённых лент.
2. Каждый заказ получает **балл релевантности**: правила из `freelance_bot/keywords.py`
   складываются, штрафы (другой мессенджер, WordPress, вакансия в штат) вычитаются,
   стоп-слова (накрутка, казино, «продам бота») выкидывают заказ совсем.
3. Заказы с баллом ≥ порога уходят в чат. Дубли не приходят повторно никогда:
   у каждого объявления стабильный `uid`, а факт отправки пишется в базу.

Пример оценки:

```
$ python -m freelance_bot filter "Нужен телеграм бот с mini app и лендингом"
Балл: 24
Теги: telegram-бот, mini app, лендинг, бот, telegram
Почему: telegram-бот +6, mini app +6, лендинг +6, бот +3, telegram +3
```

## Как выглядит сообщение

```
🔎 Разработать телеграм-бота для записи клиентов
💰 от 500 до 1 500 ₽
⏳ Срок: до 10 дн. · Предложений: 2 · Опубликован: 24 августа

Нужен бот на aiogram: запись на услуги, напоминания, оплата через
ЮKassa, выгрузка в Google Sheets. Админка для управления расписанием.

🏷 подходит по: telegram-бот, стек ботов, оплата/подписки
⭐ 18 · 📰 Kwork · Разработка и IT · 🕒 17 мин назад
👉 Открыть заказ на бирже
```

Бюджет биржи часто прячут в конце заголовка («… (Бюджет: 30 000 ₽)») — бот
вытаскивает его в отдельную строку, а раздел берёт из ленты. Если бюджет
не указан, так и пишет: «бюджет не указан».

## Где это должно крутиться

Бот присылает заказы, только пока он **запущен**. Вот способы держать его живым —
выбирай любой:

| Способ | Сервер нужен? | Задержка | Кому подходит |
|---|---|---|---|
| **GitHub Actions, репозиторий публичный** | нет | 5–60 мин, GitHub может задержать | **рекомендуется**: без сторонних сервисов, лимита минут нет |
| **GitHub Actions + внешний планировщик** | нет | ~30 мин, точно по расписанию | если репозиторий должен остаться приватным |
| **Бесплатный хостинг контейнеров** | нет | мгновенно на команды | когда важен мгновенный отклик, а компьютера под рукой нет |
| **Свой компьютер / VPS** | да | мгновенно на команды, биржи раз в 10 мин | когда нужен постоянно включённый бот |
| **Docker на VPS** | да | то же | если уже есть сервер с докером |

### Вариант 1. GitHub Actions, публичный репозиторий — рекомендуется

Публичные репозитории не расходуют лимит минут Actions вообще, поэтому можно опрашивать
каждые 5 минут без стороннего планировщика. Токен бота публикации не подлежит — он
лежит в секретах репозитория и в код не попадает. Ветка `radar-state`, где раньше
хранилось состояние (в ней был твой Telegram chat id), уже очищена — состояние теперь
живёт в кэше Actions, который снаружи не виден.

Что сделать один раз, всё — с телефона:

1. **Settings → General →** прокрутить вниз до **Danger Zone → Change repository
   visibility → Make public** и подтвердить.
2. **Settings → Secrets and variables → Actions → New repository secret** —
   создать секрет `BOT_TOKEN` со значением токена от @BotFather (если ещё не создан).
3. Написать своему боту **/start**.

Дальше ничего делать не нужно — GitHub сам опрашивает биржи каждые 5 минут
(`.github/workflows/radar.yml`, `cron: */5 * * * *`) и рассылает новые заказы.

Полезно знать:

- GitHub округляет расписание по-своему и иногда задерживает первый запуск после
  включения — наблюдалось до часа. Дальше срабатывает регулярнее, но не идеально точно;
- команды (`/score`, `/add`, `/sources`) отвечают в момент следующего срабатывания —
  обычно в течение 5–15 минут;
- прогоны без секрета `BOT_TOKEN` не падают — шаг рассылки пропускается с
  предупреждением в логе;
- биржи опрашиваются не чаще раза в 10 минут (`MIN_SOURCE_INTERVAL`) независимо от
  того, как часто просыпается бот, — это защита от блокировки по частым запросам;
- публичность касается только кода бота — своих заказов, переписки или личных данных
  в репозитории нет; все настройки фильтра живут в базе, а не в коде.

#### Если репозиторий должен остаться приватным

Тогда лимит в 2000 бесплатных минут Actions в месяц на приватный репозиторий никуда
не девается, и опрос каждые 5 минут его выбьет раньше конца месяца. Обходной путь —
внешний бесплатный планировщик, который дёргает запуск точно по расписанию, не тратя
лишних минут на пропущенные слоты:

1. секрет `BOT_TOKEN` — как в шаге 2 выше;
2. **Settings → Developer settings → Personal access tokens → Fine-grained tokens →
   Generate new token.** Доступ только к этому репозиторию, разрешение
   **Contents: Read and write** — этот токен пойдёт не в GitHub, а в планировщик;
3. зарегистрироваться на **cron-job.org** (бесплатно, без карты) и создать задание:
   - **URL:** `https://api.github.com/repos/<владелец>/<репозиторий>/dispatches`
   - **Метод:** `POST`
   - **Заголовки:** `Authorization: Bearer <токен из шага 2>` и
     `Accept: application/vnd.github+json`
   - **Тело запроса:** `{"event_type": "radar"}`
   - **Периодичность:** каждые 30 минут
4. в `.github/workflows/radar.yml` вернуть резервное расписание пореже, например
   `cron: "0 */6 * * *"`, — оно сработает, если внешний планировщик остановится.

**Почему 30 минут, а не чаще:** при этом интервале — около 1440 запусков в месяц,
с запасом до лимита в 2000 минут. При 5–10 минутах лимит будет исчерпан раньше конца
месяца, и бот замолчит до следующего.

### Вариант 2. Бесплатный хостинг контейнеров — если своего компьютера нет

В репозитории есть `Dockerfile`, поэтому бота можно развернуть прямо из браузера
телефона на любом хостинге, который умеет собирать образ из GitHub: Koyeb, Northflank,
Back4App Containers, Render (платный worker), Fly.io. Порядок везде одинаковый:

1. зарегистрироваться и подключить свой GitHub;
2. создать сервис из этого репозитория (тип — **Web service**, Dockerfile найдётся сам);
3. добавить переменную окружения `BOT_TOKEN` со значением токена от @BotFather;
4. задеплоить и написать боту `/start`.

Бот слушает порт `PORT` (по умолчанию 8080) и отдаёт по нему свой статус — это нужно
хостингам для проверки живости, а тебе — чтобы видеть, что происходит:

```json
{"статус": "работает", "заказов в базе": 78,
 "последний цикл": {"получено": 71, "новых": 3, "подходящих": 2, "отправлено": 2}}
```

Условия бесплатных тарифов меняются: где-то просят привязать карту, где-то сервис
засыпает без запросов. Если сервис засыпает — держать его разбуженным можно бесплатным
пингом (например, cron-job.org раз в 5 минут на адрес статуса).

### Вариант 3. Свой компьютер или VPS — самый предсказуемый

Тут бот работает постоянно и отвечает на команды мгновенно. Запуск одной командой:

```bash
./start.sh          # macOS и Linux
start.bat           # Windows — двойной клик
```

Скрипт сам создаст окружение, спросит токен от @BotFather (сохранит в `.env`,
который не попадает в git) и запустит бота. Дальше — `/start` в Telegram.

## Быстрый старт

```bash
git clone <этот репозиторий>
cd claude-code

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впиши BOT_TOKEN, полученный у @BotFather

python -m freelance_bot run
```

Дальше в Telegram: открой своего бота и нажми **/start**.

### Docker

```bash
cp .env.example .env      # впиши BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```

### systemd

Готовый юнит — в `deploy/freelance-bot.service` (положить проект в `/opt/freelance-bot`,
создать там venv, затем `systemctl enable --now freelance-bot`).

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | включить рассылку |
| `/stop` | выключить рассылку |
| `/check` | опросить биржи прямо сейчас и показать отчёт |
| `/last [N]` | последние найденные подходящие заказы (по умолчанию 5) |
| `/search <текст>` | поиск по уже собранным заказам |
| `/status` | состояние: источники, счётчики, твои настройки |
| `/score <N>` | минимальный балл релевантности (обычно 4–8) |
| `/keywords` | какие правила сейчас работают |
| `/add <слово> [вес]` | своё ключевое слово, `*` = любое окончание: `/add уведомлени* 6` |
| `/ban <слово>` | слово-исключение: такие заказы не приходят |
| `/del <слово>` | убрать своё слово |
| `/sources` | список лент и их состояние (✅ / ⚠️ с текстом ошибки / ⏸) |
| `/addsource <имя> <url>` | добавить RSS-ленту биржи |
| `/delsource <имя>` | удалить ленту |
| `/togglesource <имя>` | временно выключить/включить ленту |

Любой текст без команды бот воспринимает как быстрый поиск по найденным заказам.

Настройки `/score`, `/add`, `/ban` — **личные для каждого чата**, поэтому одного бота
можно спокойно использовать вдвоём или в группе.

## Командная строка

```bash
python -m freelance_bot run                  # запустить бота (то же, что без аргументов)
python -m freelance_bot once                 # один цикл: опросить, разослать и выйти (для cron)
python -m freelance_bot dryrun               # опросить биржи и вывести находки в консоль
python -m freelance_bot filter "текст"       # посмотреть, как оценивается конкретный текст
python -m freelance_bot probe <url> [url…]   # проверить, отвечают ли ленты бирж
python -m freelance_bot -v run               # подробные логи
```

`dryrun` и `filter` работают без токена Telegram — удобно подбирать ключевые слова.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | токен от [@BotFather](https://t.me/BotFather), обязателен |

| `ADMIN_IDS` | — | id админов через запятую (задел на будущее) |

Ленты проверены **26.08.2026** реальным запуском из сети GitHub Actions
(режим `probe`/`sample`, см. ниже):

| Биржа | Адрес | Результат |
|---|---|---|
| **Kwork · Разработка и IT** | `https://kwork.ru/projects?c=41` | ✅ биржа заказов, ~12 проектов на странице |

| **FL.ru** | `https://www.fl.ru/rss/all.xml` | ✅ работает, ~60 заказов за запрос (платная биржа, но пользователь оставил её в источниках) |
| Хабр Фриланс | `tasks.rss`, `tasks/rss`, `tasks.atom`, `freelansim.ru` | ❌ 410 Gone — лента закрыта |
| Freelance.ru | `/rss/projects`, `/rss/all`, `/projects/rss` | ❌ 404 |
| Weblancer | `/rss/projects/` | ❌ 403 — режет запросы из дата-центров |
| Kwork RSS | `/rss` | ⚠️ отдаёт услуги продавцов, поэтому используется страница заказов |
| Freelancehunt / Upwork | `/projects/rss*`, `/ab/feed/jobs/rss` | ❌ 403 |
| YouDo / Workspace | `/rss`, `/rss/tenders/` | ❌ пусто / 404 |
| Fiverr | категории, `/rss/gigs` | ❌ 403 — открытой ленты заявок у Fiverr нет |
| Jobbers.io | главная, `/rss`, `/projects` | ❌ 403 Cloudflare-челлендж, репутация не проверена |
| napodrabotku.ru | `/jobs-freelancers/...` | ⚠️ похож на SEO-каталог бытовых услуг, не IT-биржа |
| Хабр Фриланс (Telegram) | `t.me/s/freelansim_ru` | ⚠️ канал жив и постит заказы, но ссылки на них (`u.habr.com/...`) отдают 410 «Сервис закрылся навсегда» |

По умолчанию включены три источника: FL.ru и две категории Kwork. У Kwork нет
RSS для заказов, но страница отдаёт готовый JSON (`wantsListData`) — его и
разбирает отдельный источник `kind="kwork"`. Заказы приходят с вилкой
бюджета, сроком и числом уже поданных предложений. Каждая категория Kwork
отдаёт вторую страницу с другими заказами (id не пересекаются) — источник
забирает обе страницы сам, без настройки.

Публичные read-прокси для обхода блокировок дата-центров проверены и не помогают
(allorigins 408, r.jina.ai 403, codetabs 522), но код для них есть в `sources/rss.py` —
включается переменной `RSS_MIRRORS=1`, на случай если понадобится для новой ленты.

Проверить свои адреса можно, не поднимая бота:

```bash
python -m freelance_bot probe https://site.ru/rss https://other.ru/feed
```

или через **Actions → Радар заказов → Run workflow → mode: probe** и список адресов
в поле `urls`. Если адрес отдаёт HTML, а не RSS, — `python -m freelance_bot sample <url>`
покажет встроенный JSON (если есть), посты Telegram-канала или видимый текст страницы,
чтобы понять, можно ли это разобрать.

С домашнего IP часть закрытых лент (Weblancer, поисковые ленты бирж) может работать —
тогда добавь их командой `/addsource`.

Биржи иногда меняют адреса лент и закрывают их от «неизвестных» клиентов. Поэтому
состояние каждой ленты видно в `/sources`: если там ⚠️ с ошибкой (403, 404, timeout) —
поменяй адрес на актуальный:

```
/delsource habr
/addsource habr https://freelance.habr.com/tasks.rss?q=telegram Хабр Фриланс
```

Так же добавляются любые другие ленты: тематический поиск на бирже, RSS Telegram-канала
с заказами через сторонний rss-мост, персональная лента с фильтрами биржи.

### Свой тип источника (не RSS)

Если у биржи нет RSS, добавь класс-наследник `Source`:

Так же устроены Kwork (`freelance_bot/sources/kwork.py`, разбор JSON внутри HTML)
и публичные Telegram-каналы (`freelance_bot/sources/telegram_channel.py`, разбор
постов вида «Подборка заказов ...: 1. Заголовок (цена) ссылка 2. ...» — так шлёт
заказы канал Хабр Фриланса; подходит для любого канала с похожим форматом, если
найдётся такой с живыми ссылками на заказы).

```python
# freelance_bot/sources/my_board.py
from .base import Source
from ..models import Order

class MyBoardSource(Source):
    async def fetch(self, session) -> list[Order]:
        async with session.get(self.config.url) as response:
            payload = await response.json()
        return [
            Order(
                source=self.name,
                external_id=str(item["id"]),
                title=item["name"],
                url=item["link"],
                description=item["text"],
            )
            for item in payload["items"]
        ]
```

и зарегистрируй его в `freelance_bot/sources/registry.py`:

```python
KINDS = {"rss": RssSource, "kwork": KworkSource, "myboard": MyBoardSource}
```

Ошибка одного источника никогда не роняет опрос: она попадает в `/sources` и в отчёт `/check`.

## Как настроить фильтр под себя

Веса правил откалиброваны на реальных заказах с бирж: отсекаются сео-продвижение,
накрутка трафика, многостраничники на Тильде и «редизайн UI/UX» — а лендинги, боты
и mini apps проходят. Слабые сигналы («сайт», «вёрстка», «стек») специально не
пробивают порог в сумме.

Базовый профиль лежит в `freelance_bot/keywords.py` (`INCLUDE_RULES`, `PENALTY_RULES`,
`STOP_RULES`) — это регулярки по нормализованному тексту, поэтому «Телеграм-бот»,
«телеграм бот» и «TELEGRAM_BOT» распознаются одинаково.

Обычно править файл не нужно, хватает команд:

```
/score 6                 # строже: меньше случайных заказов
/add telegram stars 6    # своя тема
/add уведомлени*         # «*» — любое окончание, вес по умолчанию 5
/ban wordpress           # мусор, который надоел
/keywords                # посмотреть, что сейчас включено
```

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest -q          # 100 тестов: фильтр, парсер RSS, база, сервис, команды бота
```

Структура:

```
freelance_bot/
├── app.py          — сборка Bot + Dispatcher: постоянный режим и один цикл
├── cli.py          — run / once / dryrun / filter / probe / sample
├── bot.py          — команды Telegram
├── service.py      — цикл опроса, фильтрация, рассылка, дедупликация
├── matcher.py      — оценка релевантности
├── keywords.py     — профиль тем: боты, mini apps, лендинги
├── models.py       — Order (единый формат заказа)
├── storage.py      — SQLite: подписчики, заказы, доставки, слова, источники
├── formatting.py   — тексты сообщений
└── sources/        — источники: base / rss / kwork / registry
tests/              — pytest
```

Заказы старше 30 дней автоматически удаляются из базы после каждого цикла, а в режиме
`once` база дополнительно ужимается: у старых записей остаётся только идентификатор,
чтобы защита от повторов работала, а файл состояния не рос.

## Про cron

Своё расписание вместо GitHub Actions (например, на VPS без постоянного процесса):

```cron
*/10 * * * * cd /opt/freelance-bot && .venv/bin/python -m freelance_bot once >> radar.log 2>&1
```
